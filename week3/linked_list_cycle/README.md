# Linked List Cycle

## 1. Проблема
Дан головной узел односвязного списка. Определить, содержит ли список цикл (петлю).

## 2. Подход
Используется **Алгоритм Флойда («заяц и черепаха»)**:
- Указатель `slow` двигается на 1 шаг, `fast` — на 2 шага.
- Если цикла нет, `fast` дойдет до конца (`None`), и вернется `False`.
- Если цикл есть, `fast` догонит `slow` внутри цикла, условный оператор `slow == fast` вернет `True`.

### Пошаговая трассировка алгоритма
**Входные данные:** Список `3 -> 2 -> 0 -> -4`, узел `-4` указывает на `2`.

| Итерация | Позиция `slow` | Позиция `fast` | Совпадение (`slow == fast`) |
|---|---|---|---|
| **Старт** | Узел `3` | Узел `3` | `True` (старт) |
| **Итер 1** | Узел `2` (+1) | Узел `0` (+2) | `False` |
| **Итер 2** | Узел `0` (+1) | Узел `2` (+2) | `False` |
| **Итер 3** | Узел `-4` (+1) | Узел `-4` (+2) | **`True` (Столкновение)** |

**Результат:** `True` (Цикл найден)

## 3. Анализ сложности
- **Временная сложность:** $O(N)$. Если цикла нет — $\lceil N/2 \rceil$ шагов. Если цикл есть — встретятся за $O(N)$ шагов.
- **Пространственная сложность:** $O(1)$ дополнительной памяти (только два указателя).

## 4. Рефлексия / Улучшения
- **Альтернатива с Hash Set:** Запоминать узлы в `set`. Время $O(N)$, но память $O(N)$.
- **Итог:** Алгоритм двух указателей Флойда оптимален, так как экономит память ($O(1)$ вместо $O(N)$).
