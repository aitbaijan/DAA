# Merge Two Sorted Lists

## 1. Проблема
Даны указатели на головные узлы двух отсортированных односвязных списков, `list1` и `list2`. Необходимо объединить их в один отсортированный связный список, переключая указатели существующих узлов, и вернуть головной узел нового списка.

## 2. Подход
Используется **итеративный подход двух указателей с фиктивным узлом (dummy node)**:
- Создается фиктивный узел `dummy = ListNode(-1)`, выступающий в роли якоря перед началом результирующего списка.
- Указатель `current` инициализируется на `dummy` и перемещается по мере построения списка.
- В цикле сравниваются значения узлов `list1` и `list2`, меньший прикрепляется к `current.next`.
- Когда один из списков заканчивается, остаток второго списка напрямую прикрепляется к `current.next`.

### Пошаговая трассировка алгоритма
**Входные данные:** `list1 = [1 -> 2 -> 4]`, `list2 = [1 -> 3 -> 4]`

| Шаг | Состояние `list1` | Состояние `list2` | Действие | Цепь (`dummy -> ...`) | `current` |
|---|---|---|---|---|---|
| **Инит** | `1 -> 2 -> 4` | `1 -> 3 -> 4` | Создание `dummy = -1` | `-1` | `-1` |
| **Итер 1** | `1 -> 2 -> 4` | `1 -> 3 -> 4` | `1 <= 1` $\rightarrow$ берем `list1` (1) | `-1 -> 1` | `1` (list1) |
| **Итер 2** | `2 -> 4` | `1 -> 3 -> 4` | `1 < 2` $\rightarrow$ берем `list2` (1) | `-1 -> 1 -> 1` | `1` (list2) |
| **Итер 3** | `2 -> 4` | `3 -> 4` | `2 < 3` $\rightarrow$ берем `list1` (2) | `-1 -> 1 -> 1 -> 2` | `2` |
| **Итер 4** | `4` | `3 -> 4` | `3 < 4` $\rightarrow$ берем `list2` (3) | `-1 -> 1 -> 1 -> 2 -> 3` | `3` |
| **Итер 5** | `4` | `4` | `4 <= 4` $\rightarrow$ берем `list1` (4) | `-1 -> 1 -> 1 -> 2 -> 3 -> 4` | `4` (list1) |
| **Конец** | `None` | `4` | `list1` пуст $\rightarrow$ цепляем остаток `list2` | `-1 -> 1 -> 1 -> 2 -> 3 -> 4 -> 4` | `4` (list2) |

**Результат:** `dummy.next` $\rightarrow$ `1 -> 1 -> 2 -> 3 -> 4 -> 4`

## 3. Анализ сложности
- **Временная сложность:** $O(N + M)$, где $N$ и $M$ — количества узлов в списках. Цикл выполняется не более $N + M$ раз.
- **Пространственная сложность:** $O(1)$ дополнительной памяти. Используются только ссылки на существующие узлы.

## 4. Рефлексия / Улучшения
- **Существует ли более эффективный подход?** Сложности $O(N + M)$ по времени и $O(1)$ по памяти являются оптимальными.
- **Альтернатива (Рекурсия):** Занимает $O(N + M)$ памяти из-за стека вызовов, поэтому итеративный метод предпочтительнее.
